# Work Index (read this first, then read the sources)

Any agent writing copy about Sujin's work (pitch pages, app text, outreach, cover letters)
MUST read the sources below BEFORE writing. Do not write from a subset; do not write from
memory of a previous session. This index exists so nothing is written with partial knowledge.

## Sources, in reading order

1. `content/career-facts.md`. Verified roles, titles, dates, and project facts, checked
   against the resume and source code. On ANY conflict with other sources, this file wins.
2. `content/asset-inventory.md`. The full catalog of what Sujin has built: every project,
   stack, proof points. This is the depth: read the whole thing, not just the project you
   think matches. Known stale spots are corrected by career-facts (Bull not BullMQ, no
   Jupiter routing at Beans, Beans dates). Commit counts and repo internals in it are
   context for you, NEVER copy for the page.
3. `companies/evidence.ts`. The exhibit library. Requirement `proofs` may only use:
   vanta-os, beans, keom, society-mobile, mudrex.
4. `content/copy-corpus.md`. Voice reference, locked story structure, banned patterns.
5. `CLAUDE.md` Copywriting Rules + Evidence Rules sections.

## Rules of use

- Pick evidence by what the work actually was, not by number size. If a JD asks for
  something (e.g. reconciliation) and the biggest number doesn't match it, search the
  inventory for the work that does. Never relabel work with the JD's theme word.
- If no source supports a fact, the fact does not go on the page. Write around it or
  flag it back instead of inventing.
